# Phonon-2 Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Fermion Research's Phonon-2 as a benchmarkable engine (`phonon-2`) reachable over two transports, `http` (`phonon serve`) and `cli` (`fermion transcribe --json`, native or via `docker run`).

**Architecture:** One new engine family, `engines/phonon.py`, following the `engines/hf.py` / `engines/nim.py` pattern: a `PhononEngine` that scores clips, plus a swappable `PhononClient` (`HttpPhononClient`, `CliPhononClient`, `FakePhononClient`) doing the transcription. Everything except "transcribe one clip" is shared. The http client splits long clips to stay under the server's 32 MB request cap; the cli client does not.

**Tech Stack:** Python stdlib only (`urllib`, `subprocess`, `wave`, `array`, `shlex`, `http.server` in tests); pytest.

**Spec:** `docs/superpowers/specs/2026-10-04-v0.6-phonon-engine-design.md` (read its "Transport parity ledger" first; Task 7 reconciles the spec with the decisions below).

## Global Constraints

- Core stays **torch-free with no new dependencies**; `schema_version` stays **1**; changes are **additive** (output for runs without `phonon-2` is byte-stable).
- Model id `phonon-2`; engine name `phonon`; only Phonon-2 (no Phonon-1 family, no `phonon:<model>` ad-hoc ids).
- http server body cap is **32 MB**: send one request if the WAV is <= **24,000,000 bytes**, else split into pieces of about **600 s**, each cut at the lowest-energy 20 ms frame within **+/-10 s** of the target boundary.
- Request fields: `file`, `model=phonon-2`, `response_format=verbose_json`, `timestamp_granularities[]=word` and `=segment`; body is non-chunked (`Content-Length` set); auth header `Authorization: Bearer <key>` only when a key is given.
- cli command: `<phonon_cmd> transcribe phonon-2 <path> --json`; stdout is the JSON only. http words use key `word`; cli words use key `text`.
- `phonon_api_key` is **never** written to the JSON sidecar or the reproduce command.
- **Parallel-implementations rule:** any change to one transport is mirrored to the other, or the divergence is recorded in the spec's parity ledger in the same commit. The contract test (Task 4) enforces this.
- Tests run with the project venv: `.venv/bin/python -m pytest` (Windows: `.venv\Scripts\python -m pytest`). **Baseline before this work: 285 pass, 2 fail, 2 skipped**; the 2 failures (`tests/test_results_json.py::test_main_writes_json_sidecar_with_output`, `::test_main_no_json_flag_skips_sidecar`) are pre-existing (WhisperX needs torch/venv on this machine). Expect no *new* failures.
- Commit after every task, ending the message with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Never `git add -A`; stage named paths.

## Review Focus

Each line below is pinned by a test in the named task.

1. **Empty transcript** (silent clip: `text == ""`, no segments/words): clip scores without crashing, writes no empty VTT. (Task 5)
2. **No `words` in the response** (or `words` null): VTT falls back to `segments`; no `_Words_` file. (Task 5)
3. **Split boundaries:** a clip just under the 24 MB threshold sends one request; just over sends several whose sample ranges are contiguous with no gap, overlap, or empty piece. (Task 2)
4. **Awkward paths with the Docker template:** filename with spaces/unicode and a clip that needs decoding (mp4) still map to `/audio/<name>` and run. (Task 4)
5. **A piece fails mid-clip** (piece 2 of 3 returns 500) or the server dies: the whole clip fails; a partial transcript is never scored. (Task 3)
