# v0.6 — Phonon-2 engine (design)

**Status:** approved in conversation 2026-10-04; revised 2026-10-25 (two transports; 32 MB cap fix; parity ledger). Awaiting review.
**Branch:** `feat/v0.6-phonon` (off `main`; independent of the unmerged `feat/mlx-wtm-consensus`).

## Credit

Phonon is the speech recognition engine from **Fermion Research** —
<https://github.com/fermionresearch/phonon> (Apache-2.0 CLI/server). The
**Phonon-2** model (<https://huggingface.co/FermionResearch/Phonon-2>, CC-BY-4.0)
is a derivative of NVIDIA's `parakeet-tdt-0.6b-v3`. asr-bench only *calls* a
Phonon server; it bundles none of Phonon's code or weights.

## Goal

Benchmark **Phonon-2** alongside the existing engines in one report, on the
reference box (Firefly, RTX 5090), so it can be compared head-to-head with
`parakeet-tdt-0.6b-v2` (its architectural ancestor's sibling), Whisper Large V3
Turbo and distil-large-v3.5.

**Out of scope (YAGNI):** Phonon-1 / Phonon-1 Big / Phonon-1 Micro (different
CUDA image, no timings), a `phonon:<model>` ad-hoc id, asr-bench
starting/stopping/pulling containers (it only invokes `docker run` for the CLI
transport), live-mic (`listen`), hotwords.

## Approach — two transports, one engine

`PhononEngine` supports **both** ways of running Phonon, selected by flag:

- **`http`** — talk to a running `phonon serve` (OpenAI-compatible
  `/v1/audio/transcriptions`), like NIM's `--nim-url`. Model loads once; reaches
  a CUDA container on Firefly, native MLX `fermion serve` on Apple silicon, or
  the CPU build. **Constraint:** the server caps a request body at **32 MB**
  (about 16 min of 16 kHz mono WAV; FLAC only stretches that to ~30 min — not
  enough for ~50-min lectures), so long clips are **split client-side**.
- **`cli`** — run `fermion transcribe phonon-2 <file> --json` per clip (native
  install) or the same subcommand inside the CUDA image via `docker run`. Takes
  a file path, so **no size cap and no splitting**; the model reloads per clip
  (a few seconds against a long decode).

Everything that is not the act of transcribing one file is shared (see
**Transport parity ledger**). Neither transport needs a venv or runner script.

## Components

### Registry entry (`MODELS` in `asr_bench.py`)

```python
"phonon-2": {
    "engine": "phonon",
    "display": "Phonon-2",
    "params_m": 600,          # parakeet-tdt-0.6b-v3 derivative
    "disk_mb": 164,
    "notes": "Fermion Research Phonon-2 via OpenAI-compatible server. Endpoint set by --phonon-url.",
}
```

### `engines/phonon.py`

- `PhononResult` dataclass — `text`, `segments`, `words`, `duration`,
  `decode_seconds` (optional); `from_verbose_json(d)`; `cue_tuples()`.
- `PhononClient` ABC with `check()` (pre-flight) and `transcribe(audio_path)
  -> PhononResult`; implementations: `HttpPhononClient` (stdlib `urllib`,
  hand-built `multipart/form-data`, client-side splitting), `CliPhononClient`
  (`subprocess`, `--json`), and `FakePhononClient` for tests. Mirrors the
  `HFAdapter`/`FakeHFAdapter` split.
- **Shared, transport-independent code** (one implementation, used by both):
  `PhononResult.from_http_json` / `from_cli_json` (both normalize to the same
  fields: `text`, `segments`, `words`, `duration`, `decode_seconds`), VTT/words
  sidecar writing, ffmpeg decode, scoring, error-to-`ClipResult` mapping.
- `PhononEngine(Engine)` — `run(entry, pairs, cfg) -> ModelResult`.
- Registered in `engines/__init__.py` as `ENGINES["phonon"]`; re-exported from
  `asr_bench.py`.

### CLI flags / config

| Flag | Default | `RunConfig` field | Sidecar |
|---|---|---|---|
| `--phonon-transport` | `auto` (`http`\|`cli`) | `phonon_transport` | recorded |
| `--phonon-url` | `http://127.0.0.1:8000` | `phonon_url` | recorded |
| `--phonon-api-key` | `None` (also `PHONON_API_KEY` env) | `phonon_api_key` | **redacted**, like `nim_api_key` |
| `--phonon-cmd` | `fermion` | `phonon_cmd` | recorded |

- `auto`: `--phonon-url` given -> `http`; else `--phonon-cmd` given or `fermion`
  on PATH -> `cli`; else `http` against the default URL.
- API key is sent as `Authorization: Bearer <key>` (http only).
- `--phonon-cmd` is an argv prefix. For Docker, pass e.g.
  `docker run --rm --gpus all -v {dir}:/audio -v phonon-cache:/home/phonon/.cache ghcr.io/fermionresearch/phonon-cuda:1.0.5`;
  when the template contains `{dir}`, asr-bench mounts the decoded clip's temp
  directory there and passes `/audio/<name>` as the path. asr-bench then appends
  `transcribe phonon-2 <path> --json`.

## Data flow (per clip)

Steps 1, 4 and 5 are shared; steps 2-3 differ by transport.

1. **Decode.** Phonon reads wav/flac/ogg/aiff only. Anything else (the lecture
   corpus is mp4) is converted by the ffmpeg CLI to a temp 16 kHz mono WAV,
   same approach as `nemo_runner.py`/`hf_runner.py`; temp files are removed
   after the request.
2. **Request.**
   - **http:** if the WAV is <= ~24 MB (headroom under the 32 MB cap), one
     `POST {phonon_url}/v1/audio/transcriptions` with `file`, `model=phonon-2`,
     `response_format=verbose_json`, `timestamp_granularities[]=word`
     (also `segment`); non-chunked body (the server rejects chunked transfer
     encoding). Longer clips are **split into <= ~10-min pieces**, each cut at
     the lowest-energy point within +/-10 s of the target boundary (so a word is
     not bisected); one request per piece; word/segment times are shifted by the
     piece's start offset and the results concatenated in order. Each piece is
     checked against the cap before sending; one still over it fails the clip
     with a clear message (no silent truncation).
   - **cli:** one subprocess per clip, `<phonon_cmd> transcribe phonon-2 <path>
     --json`; stdout is the JSON object only (all chatter is on stderr). No
     splitting.
3. **Parse** the transport's JSON into the shared `PhononResult`:
   - http `verbose_json`: `text`, `segments[{start,end,text}]`,
     `words[{word,start,end}]`, `duration`, `x_fermion.decode_seconds`.
   - cli `--json`: `text`, `segments[{start,end,text}]`,
     `words[{text,start,end}]` (**key is `text`, not `word`**),
     `duration_seconds`, `decode_seconds`, `wall_seconds`, `truncated`.
   - Optional fields are read defensively, never required. If `truncated` is
     true (cli), the clip is flagged in notes (part of a window may be missing).
4. **Outputs.**
   - Transcript → scored normally (WER/MER/WIL/CER, S/D/I, hallucination signals).
   - `<base>_Captions_Phonon-2.vtt` — cues built from `words` (readable
     gap/length grouping via `hf_runner._segments_from_words` — torch-free at
     module level, so importable from core; `_needs_decode`/`_ffmpeg_to_wav`
     are reused the same way), falling back to `segments` when `words` is absent. Segments
     alone are 25–35 s windows — too long to be good captions, hence words first.
   - `<base>_Words_Phonon-2.json` — the word list.
5. **Timing / resources.**
   - **RTFx** uses client-measured wall time for the whole clip: http = all
     requests (upload + decode + response, summed over pieces); cli = the
     subprocess (**includes model load**). `decode_seconds` (decode only, summed
     over pieces) is recorded in the sidecar per clip when present (additive
     field) but not used for the headline. The cli/http difference is a
     documented divergence (ledger row P7).
   - **Peak VRAM** = `n/a` (the GPU is in another process / box), noted in the
     report's "Engines in this run" section like NIM.
   - **Disk** = 164 MB (registry value).

## Error handling

- **Pre-flight in `main()`** (only when `phonon-2` is requested), via
  `client.check()`; any failure -> warn, skip `phonon-2`, other engines still
  run (same as NeMo/HF with no venv):
  - **http:** `GET /health`, then `GET /v1/models`. Unreachable -> warn;
    reachable but not serving `phonon-2` (alias or `FermionResearch/Phonon-2`)
    -> warn naming what *is* served; 401 -> "check --phonon-api-key".
  - **cli:** `<phonon_cmd> --help` (or `docker run ... --help`) must exit 0;
    command not found / Docker not running -> warn with the exact command tried.
- **Per clip:** HTTP 4xx/5xx → clip marked failed with the OpenAI error
  envelope's `message`/`code`; ffmpeg failure → clip failed; the run
  continues. All clips failed → the usual `ALL CLIPS FAILED` row.
- Timeout (http per request; cli per subprocess) scales with audio length (generous floor, e.g.
  `max(120, 2 × audio_sec)`), since the long lectures are single requests.

## Transport parity ledger (standing rule)

**Rule (Kevin, 2026-10-25):** whenever a change is made to one of a set of
parallel implementations, the same change must be made to the others, or the
reason it was not must be recorded here. This ledger is the trace. Any PR that
touches `engines/phonon.py` updates the table in the same commit; the
transport contract test (see Testing) enforces the "Same" rows mechanically.

| ID | Behavior | http | cli | Status |
|---|---|---|---|---|
| P1 | Audio decode (non-wav -> 16 kHz mono WAV) | shared ffmpeg step | shared | Same (shared code) |
| P2 | JSON -> `PhononResult` fields | `from_http_json` | `from_cli_json` | Same output; **input key differs** (`word` vs `text`) |
| P3 | VTT + `_Words_*.json` from word times | shared writer | shared | Same (shared code) |
| P4 | Pre-flight skip with warning | `/health` + `/v1/models` | `--help` probe | Same behavior, different probe |
| P5 | Per-clip failure -> `ClipResult` error | HTTP status/envelope | exit code/stderr | Same mapping, different source |
| P6 | Size limit | **32 MB cap -> split into ~10-min pieces, stitch with offsets** | none (file path) | **Diverges by design** - the cap is an HTTP-server limit only |
| P7 | RTFx wall time | request time, summed | subprocess time **incl. model load** | **Diverges** - cli pays load per clip; flagged in the report's engine note |
| P8 | Truncation signal | none exposed | `truncated` flag -> note | **Diverges** - http `verbose_json` has no equivalent field (re-check on upgrade) |
| P9 | Auth | Bearer key | n/a (local process) | **Diverges** - no network, nothing to authenticate |
| P10 | Model reuse | loaded once | reloaded per clip | **Diverges** - inherent to CLI |

Keep this table current; add a row for every new Phonon behavior.

## Compatibility

- Additive only: **`schema_version` stays 1**; `render_markdown` and the JSON
  sidecar are byte-stable for runs without `phonon-2`.
- Core stays **torch-free and adds no dependencies** (stdlib `urllib`).
- No change to any other engine.

## Testing

Unit (fake client, no network):
- `verbose_json` → text / cues / words parsing, incl. missing `words`,
  missing `x_fermion`, empty transcript.
- **Transport contract test (parity gate):** one parametrized test runs the
  *same* assertions against `HttpPhononClient` (stub HTTP server) and
  `CliPhononClient` (stub `fermion` script): same text, same cues, same words,
  same failure mapping. A new behavior added to one transport without the
  other fails this test unless it is listed as a divergence in the ledger.
- http splitting: split points, offset shifting, stitched word order, a piece
  over the cap fails the clip; cli never splits.
- cli: stub command on PATH emitting `--json`; `{dir}` Docker template
  expansion; `truncated: true` flagged; non-zero exit mapped to a clip failure.
- Multipart body construction (field names, `timestamp_granularities[]`,
  Content-Length set, no chunking) and Bearer header present only with a key.
- Pre-flight: unreachable, wrong model served, 401 → skip with warning;
  other engines unaffected.
- Non-wav input routes through the ffmpeg decode (mocked).
- Sidecar: `phonon_url` recorded, `phonon_api_key` redacted.
- A local stub HTTP server test (`http.server` on an ephemeral port) for the
  real `HttpPhononClient` round-trip.

**Live gate (Firefly):**
1. Install Docker Desktop with the WSL2 backend; confirm GPU passthrough
   (`docker run --rm --gpus all nvidia/cuda:… nvidia-smi`).
2. `docker run --rm --gpus all -p 127.0.0.1:8000:8000 -v phonon-cache:/home/phonon/.cache ghcr.io/fermionresearch/phonon-cuda:1.0.5 serve phonon-2 --host 0.0.0.0 --port 8000`
3. `python asr_bench.py --models large-v3-turbo,parakeet-tdt-0.6b-v2,phonon-2 --include "Week 16 - Friday"`
   on the same 6.8-min lecture as the 2026-06-08 snapshot.
4. Success = a real Phonon-2 WER/RTFx row + a sane VTT; record numbers in
   CLAUDE.md/AGENTS.md. Check VRAM headroom against LM Studio (Baton d043:
   one model server per box) via `nvidia-smi` during the run.

Side benefit: Docker Desktop on Firefly also unblocks the long-pending live
NIM validation (`memory/validate-live-nim.md`).
